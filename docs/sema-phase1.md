## 1. 完整导入系统设计（拍板规则）

`design.md` §4.3 只定义了路径别名的**语法**，未定义到文件系统的映射。
本期按以下规则实现（落地后回写 `design.md`）：

### 1.1 模块与路径映射

1. **模块 = 文件**：一个 `.nov` 文件即一个模块；模块 ID 为规范化后的绝对路径。
2. **前缀切分**（parser 已实现）：`:` **仅作别名分隔符，最多一个**——
   路径字符串在第一个 `:` 处切分，前段为别名（`ImportItem.prefix`）、
   后段为逻辑路径（`ImportItem.path`）；path 内再出现 `:` 报
   「路径段分隔符只支持 `/`」（`design.md` 中 `"@:sub:mod"` 示例届时
   同步修正为 `"@:sub/mod"`）。
3. **段分隔**：`path` 内只认 `/` 分段；空段（`"a//b"`、`""`）报
   「非法模块路径」。
4. **映射表**（段序列 → 文件）：

   | 导入写法 | 解析结果 |
   |---|---|
   | `"utils"` / `"sub/mod"` | 相对**当前文件所在目录**：`utils.nov` / `sub/mod.nov` |
   | `"@:sub/mod"` | crate 根（nov.toml 所在目录，见 §1.1.1）：`<root>/sub/mod.nov` |
   | `"super:xxx"` | 当前文件目录的父目录：`<dir>/../xxx.nov` |
   | `"std:exception"` | std 库根目录（当前不存在，见 §1.4） |
   | 无前缀但含 `:` | 按「未知路径别名」诊断（`design.md` §4.3.1） |

5. **模块内顶层语句**：被导入模块的顶层语句照常参与名称解析与类型检查；
   初始化执行顺序属 codegen 职责，sema 不定义（回写 `design.md` 注明）。

### 1.1.1 nov.toml（crate 根标记，新设计）

本语言的项目清单文件（对标 Cargo.toml），本期落地最小形态：

```toml
[package]
name = "my-crate"      # 包名（标识符）
version = "0.1.0"      # 语义化版本
# 预留：[dependencies]（包管理期）、[target]（多目标期）
```

- **职责（本期）**：仅作 **crate 根标记**——`@:` 别名解析时从**当前文件**
  起向上逐级查找最近的 `nov.toml`，所在目录即 crate 根；
  未找到时使用 `@:` 报「未找到 nov.toml（crate 根）」（相对导入不受影响）。
- CLI 本期只定位、不解析字段；schema 先入文档，字段校验留待包管理期。

### 1.2 加载管线（循环导入安全）

```
Phase 0  加载：worklist 队列——入口 → 词法/语法 → 收集导入 → 入队未加载模块，
         直到收敛（模块 ID 去重，天然免疫循环）；文件缺失/词法语法错误
         记诊断并跳过（可恢复，不中断其余模块）。
Phase 1  声明收集：全部模块的顶层声明（func/class/struct/trait/别名/顶层变量）
         先收集进各自模块全局作用域——全部完成后再进入 Phase 2，
         因此**循环导入允许**（对齐 Rust）。
Phase 2  绑定与解析：绑定各模块导入符号 → 解析函数体/语句体内的标识符与类型。
```

### 1.3 导入形态语义

| 形态 | 语义 | 检查 |
|---|---|---|
| `from "m" import a, b as c;` | 目标模块的 `pub` 符号 `a`/`b` 绑定为本模块名 `a`/`c` | 文件存在；符号存在；符号为 `pub`；本地名不冲突 |
| `import "m";` | 整模块绑定为命名空间（本地名取路径末段，parser 已推导） | 文件存在；别名不冲突 |
| `from "std:..." import x;` | 外部符号登记（std 库尚未落地，不参与类型检查） | 仅校验前缀合法 |

- **命名空间成员访问**：表达式位 `mod.foo()` / `mod.CONST` 经
  `MemberAccess` 解析（目标符号须 `pub`）。
- **类型位限定名**：`mod.Type` 需 parser/AST 小改（见 §1.6）；落地前
  跨模块类型引用只能用具名导入。
- 导入符号是**只读引用**：对导入变量赋值、对导入函数取址后的写操作报诊断。

### 1.4 std 处理

`std` 是合法别名；std 库目录当前不存在，`std:` 导入的符号登记为
**外部符号**（参与名称解析，不产生「未定义」误报，调用不查参数），
不实际加载文件。未来 std 落地时改为真实加载。

### 1.5 可见性

仅 `pub` 顶层符号可被跨模块导入；导入非 `pub` 或不存在的符号报诊断。
`pri` / `pkg` 本期在单 crate 内按「模块私有」处理（`pkg` 完整语义待包系统）。

### 1.6 类型位限定名（parser/AST 配套小改）

为使命名空间导入对类型完整可用，配套修改（含文法同步，约 50 行）：

- `grammar/NovellaParser.g4`：`typeReference: identifier (Dot identifier)* typeGeneric?;`
- `crates/novella-ast/src/types.rs`：`TypeExpr::Reference` 增加
  `qualifier: Vec<String>`（空 = 非限定引用，serde 字段同步）。
- `crates/novella-parser/src/types.rs`：解析限定段。
- sema：`qualifier` 非空时按命名空间导入解析目标模块，再在目标模块查
  `pub` 类型符号。

### 1.7 导入诊断矩阵

| 诊断 | 触发 |
|---|---|
| 未知路径别名 | 前缀非 `@`/`std`/`super` |
| 非法模块路径 | 空段、路径为空 |
| 模块不存在 | 映射后文件缺失 / 读取失败 |
| 导入符号不存在 | 具名导入的名字在目标模块无声明 |
| 符号不可导入 | 目标符号非 `pub` |
| 本地名冲突 | 导入绑定名与本模块声明或其他导入重名 |
| 命名空间成员不存在 / 不可访问 | `mod.x` 无此 `pub` 成员 |
| 对导入符号赋值 | 导入绑定只读 |

## 2. crate 结构

```
crates/novella-sema/src/
├── lib.rs      # analyze(entry, loader) -> SemaResult；管线编排
├── module.rs   # 模块加载：路径映射、worklist 队列、模块注册表
├── symbol.rs   # 符号表：Symbol（种类/可见性/来源模块/类型）、Scope 树
├── resolve.rs  # 两遍法：①收集各模块顶层声明 ②解析导入绑定与体内引用
├── alias.rs    # 类型别名：登记、TypeExpr 内展开、循环检测
├── ty.rs       # 语义类型 Ty 与 TypeExpr → Ty 解析（预定义类型归类）
├── typecheck.rs# 基本类型检查（表达式 / 语句 / 声明）
└── check.rs    # 声明级基础检查（main、struct 规则、__ 命名空间等）
```

- **可测试性**：`FileLoader` trait 抽象文件读取（默认 `FsLoader`），
  测试可注入内存文件系统。
- **输出**：`SemaResult { modules: Vec<AnalyzedModule>, diagnostics: Vec<Diagnostic> }`，
  诊断复用 `novella-core::Diagnostic`，CLI 侧 rustc 风格渲染已有。
- 语义错误**可恢复**：单点失败记录诊断后继续，同一文件尽量一次报全
  （对齐 `design.md` §10）；类型无法推导处用 `Ty::Error` 抑制级联误报。

## 3. 名称解析（resolve）

- 每模块一棵作用域树：模块全局 → 函数/方法 → 块级嵌套
  （含 for-init、with-binding、catch 变量、lambda 参数）。
- 查找顺序：局部 → 模块全局 → 本模块导入符号；未定义标识符报诊断。
- 重复定义检查：模块级同名符号、同作用域重复 `let/const`、类内重复成员。
- 预定义类型名（`int`/`u8`/…）在类型位按名字归类（`design.md` §5.1 已定）。

## 4. 类型表示与解析（ty / alias）

`Ty`（语义类型）变体：

```
Predefined(PredefinedType) | Struct(符号) | Class(符号) | TypeParam(不透明)
Array(Box<Ty>) | Tuple(Vec<Ty>) | Function(参数/返回) | Union(Vec<Ty>)
Pointer(Box<Ty>) | Error   // Error 用于错误抑制
```

- `TypeExpr::Reference` → 查符号表：class/struct/类型参数/别名；
  未知名报诊断。
- **类型别名**：登记后在使用处展开为 `Ty`；检测循环别名
  （`type A = B; type B = A;`）；泛型别名实参个数校验（不实例化）。
- **浅泛型**：`Foo<T>` 校验实参个数与形参一致、实参本身可解析；
  整体视为不透明类型（仅同名同 arity 相等），不做单态化与约束求解。

## 5. 基本类型检查（typecheck）

### 5.1 字面量值解析（值语义延后，design.md §2）

- 数字：十/十六/八/二进制解析（去 `_` 分隔符），整数默认 `int`、
  含小数点/指数默认 `float`；超 `i64`/`u64`/`f64` 范围报溢出诊断。
- 字符串：识别 `f/r/b` 前缀；校验转义序列（`design.md` §3.3「非法转义
  留待语义阶段」）；`f"..."` 插值表达式解析与检查。
- `null` → `void*`（§6.5 S9）；布尔 → `boolean`。

### 5.2 表达式类型规则

- 一元：`+ - ~` 数值；`!` boolean；`&x` 左值 → `T*`（S1）。
- 二元：算术 `+ - * / %` 数值；位运算与移位整数；比较 `< > <= >=` 数值
  → `boolean`；`==`/`!=` 同类型可比（**struct 值非法**，§8.5）；
  `&&`/`||` 两侧 boolean；`??` 左操作数可空，结果为非空分支类型。
- 赋值兼容（**拍板**：不做隐式数值转换，须显式 `as`；仅以下隐式）：
  `null` → 任意 `T*` / class 引用；`void*` → 任意 `T*`（S8/S9）。
- `as` 转换按 §6.3 矩阵的**类型合法性**判定（unsafe 上下文要求见 §7 建议）。
- 条件表达式（`if/while/for` 条件、三元条件）须 `boolean`。
- 数组字面量：元素类型一致（取首个元素类型为基准）；
  元组/对象字面量按结构构造类型；对象字面量简写 `{b}` 展开为 `b: b`（§4.12）。

### 5.3 访问与调用

- 成员访问：struct/class 字段与方法解析（含 `static` 成员的访问形态校验）；
  不存在成员报诊断。
- 索引：`T[]` 以整数索引 → `T`；指针 `p[i]` → `T`（S3）。
- 函数调用：实参个数（含默认参数）与类型逐个匹配；`new Foo(...)` 按
  `__init` 签名匹配；`Point{ x: 1 }` 按字段集合检查（未知字段 / 缺失且
  无默认值的字段报诊断，§5.4）。
- `return` 值与函数返回注解匹配；无注解函数按首个 `return` 推导
  （后续不一致报诊断）。
- **类型标注下推（双向检查）**：带标注的 `let/const` 把标注作为期望类型
  传入表达式检查——空数组字面量 `let a: int[] = [];` 由标注定元素类型
  （无标注才报「无法推断元素类型」），`null` 字面量同理按标注定型。
- **错误级联抑制**：`Ty::Error` 表示「产生处已报明确诊断」（未定义标识符 /
  未定义类型 / 不能 `new` 的类型），沿表达式传播时不再重复报错，避免一处
  笔误刷出整串级联诊断。

### 5.4 语句上下文

- `break`/`continue` 仅循环内；`return` 仅函数内；
  `let (a, b) = ...` 元组解构按元素类型逐个绑定。

## 6. 声明级基础检查（check）

| # | 规则 | 依据 |
|---|---|---|
| 1 | `main` 入口：仅入口模块检查——顶层、无参、无泛型、返回 `void`/`int`；缺 main 报错 | §4.8.1 |
| 2 | struct 不得有继承（`heritage` 非空报错） | §4.7 |
| 3 | struct 方法名不得 `__` 开头 | §4.7 |
| 4 | class 特殊方法登记清单：`__init`/`__destroy`/`__str`/`__enter`/`__exit`；普通方法不得 `__` 开头，未登记的 `__` 名报错 | §4.6.1 |
| 5 | `yield` 语句报「尚未支持」（warning：语法保留、语义待定，不阻断编译） | §9.4 |
| 6 | 导入本地绑定名与模块内符号冲突检测 | — |

## 6.1 extern 函数（FFI 边界）

`extern func` 声明外部函数（§4.8），sema 处理规则：

| # | 规则 | 说明 |
|---|---|---|
| E1 | **正常登记进符号表**（种类 `ExternFunction`） | 可被本模块调用、可被 `pub extern` 跨模块导入；调用点**与普通函数同一套完整类型检查**（实参个数/类型/默认值）——这是 extern 的核心价值：FFI 调用必须可查错 |
| E2 | 参数与返回类型**必须显式标注** | FFI 边界无函数体、无法推导；缺标注报诊断（普通函数允许推导的规则不适用） |
| E3 | 不得有函数体 | 文法已强制 `;` 结尾，sema 防御性复查 |
| E4 | 不得带泛型参数 | FFI 边界无单态化；`extern func f<T>(...)` 报「暂不支持」 |
| E5 | 不得命名为 `main` | 入口必须有函数体 |
| E6 | 调用约定 / 链接名 | 由 `@extern("C")` 类指令承载（§4.5 指令解释属后续期）；本期 extern 默认 C ABI，不在 sema 校验 |
| E7 | **调用 extern 函数必须在 `unsafe { }` 上下文** | FFI 边界不受语言安全保证（对齐 Rust `unsafe extern fn`）；unsafe 外调用报诊断。复用 §7-A 的 `in_unsafe` 上下文标志。此规则回写 `design.md` §4.8 |

## 8. CLI 接入与文档

- `novella-cli compile`：**只调用 `novella_sema::analyze` 一次**，不再自行
  跑 lexer / parser（此前入口文件会被解析两次）。CLI 从
  `SemaResult.modules` 取入口的 `tokens` / `program` / `syntax_diagnostics`
  写 JSON，从 `diagnostics.modules` 取语义诊断；两处渲染都用模块自带的
  `source`，不回盘重读。
- 诊断输出：global 诊断 → 各模块词法/语法诊断 → （零错误时）`共 N 个错误`
  → 各模块语义诊断 → 语义错误汇总。零错误时不打印 `共 0 个错误`。
- JSON 字段（**不兼容变更：直接替换**，无迁移）：`tokens` / `program` /
  `diagnostics`。**诊断只有一棵树**，不再有 `sema_diagnostics` 之类的第二份：
  `diagnostics` = `{ global: [...], modules: [{ id, path, diagnostics: [...] }] }`；
  每个模块的 `diagnostics` 已把词法 / 语法 / 语义三种诊断按**源码位置**
  （`location.span.start`）合并排序，同一处只出现一次，与 stderr 顺序一致。
- 诊断里的 `location.file` 与 `sema_diagnostics[].path` 由规范化绝对路径
  改为**调用方传入的原始路径**（如 `test.nov`），便于对照命令行参数。
- 行为修复：导入模块的语法错误现在能被渲染（旧 CLI 只解析入口，完全丢失）。
- 文档同步：`docs/compiler-design.md`（sema 段落不再是占位）、根 `AGENTS.md`
  （结构与 CODE MAP）、`docs/design.md`（回写 §1 拍板的模块映射规则）。
