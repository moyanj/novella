# sema 补全实施计划（供接手 AI 逐项执行）

> 基于 2026-11-15 工作区源码核对；不是完成报告。
> 本次只编写计划，不修改编译器实现。目标是补全 sema，而非立即接 LLVM。
> 接手 AI 必须顺序执行小任务，不能把“HIR 拒绝了”当作“sema 已正确检查”。

## 1. 完成标准与执行边界

“sema 完整”必须相对于一份明确的语言规则清单判断：每项已定规则都有检查入口、正反例和正确定位；待定规则单独列出，不能靠 Unknown、warning 或后端错误掩盖。

分为三个验收点，禁止混淆：

1. **A：现有规则漏洞修补完成**：下文 S00–S08 中无决策依赖的任务完成。
2. **B：已确认语言范围覆盖完成**：所需决策确定后，S09–S13 完成，并同步 HIR/LSP。
3. **C：整体交付完成**：S14 的规则矩阵没有未处理的已定规则；仍有待定语言能力时，只能报告 A/B 及剩余条目，不能宣布“全部 sema 完成”。

不包含 LLVM 接入、链接器、ARC 指令、异常栈展开或异步状态机的运行时实现。**这些运行时未实现，不等于无需检查对应的静态类型规则。**

本计划不授权修改未确定的语言规则，也不授权大规模接口/架构改造。若任务需要这类变更，先交付具体设计、影响文件及兼容性说明，再等待确认；其余不依赖该决策的任务可以继续。

下面“已核实”指已阅读当前实现；尚未逐项运行反例，接手 AI 仍需先复现再修。

| E11 | design §9.2：赋值先 RHS 再 LHS；HIR `build_assignment`：先地址再 RHS | 当前 HIR 与设计冲突；此前“求值顺序已修好”的交付措辞不充分，需单独纠正 |

## 4. 决策清单：有依赖的任务必须等明确答复

先复核 `design.md` 是否已经提供答案；若有明确答案，引用它执行，不重复询问。以下是真实存在的待定或冲突点，按受影响任务逐批询问，不能开工时一次塞给用户全部问题。

| 决策 | 需要确定的内容 | 不可擅自做的事 |
| --- | --- | --- |
| D01 赋值顺序 | 普通赋值按 design §9.2 保持 RHS→LHS；复合赋值的定位、读旧值、RHS 顺序需补明确规则。若打算改为 LHS 优先，须用户确认 | 不把当前 HIR 行为倒写进设计来掩盖冲突 |
| D02 成员与继承 | 未标可见性的成员默认权限、pri 的访问范围、静态成员能否经实例访问、覆写签名/字段遮蔽/抽象类实例化规则 | 不直接套用 Rust/Java/C++ 的整套规则 |
| D03 类型推导 | 无注解形参是否本阶段仍容错；是否启动参数推导；未初始化局部的合法读取规则 | 不把“无注解返回缺省 void”改成推导；不擅自新增 borrow checker |
| D04 trait | class 如何声明实现 trait、是否结构化实现、默认方法/字段需求、兼容性和约束规则 | 当前语法不足时不得发明 impl/冒号语法；不能用空 TraitDef 宣称支持 |
| D05 泛型 | 本轮覆盖显式类型实参代入到什么程度、是否允许推导、约束和递归实例处理 | 不用同名 TypeParam 表示不同声明的形参；不把 arity 检查称为实例化 |
| D06 match | 值 match 的穷尽要求、布尔/联合/类型模式的判定、块分支是否有值、未覆盖时行为 | 不用 HIR 的 default 限制反推语言必然要求 default |
| D07 对象与字符串 | 匿名对象是否结构类型、b 字符串的类型、支持哪些转义和 f-string 插值语法、f8/f16 溢出与表示标准 | 不发明 bytes/object 的值表示或精度格式 |
| D08 异常与异步 | std Exception 的真实类型来源、Future 的语言类型及可写法、with as 绑定原值还是 __enter 返回值、特殊方法签名 | 不把任意 class 自动当 Exception；不把 async 调用直接当返回 T |

D01 中普通赋值已有规范，应先按规范处理；只有复合赋值未明确的细节或改规范的提案需要确认。

## 5. 每项任务统一执行模板

接手 AI 每次只做一个 S 编号；大任务中的子项也要逐项验收。

1. 读指定函数及其调用方，确认当前源码与本文一致；不一致先更新现状记录。
2. 构造一个最小反例，记录实际语法/语义诊断；**语法失败不能当 sema 成功拒绝**。
3. 写出规则依据、最小改法和会受影响的消费者；若跨越决策门，停该任务请求确认。
4. 修实现，再跑反例、相邻合法例和至少一个边界例；错误例必须具有相应语义诊断与正确 span。
5. 跑本任务检查并更新执行记录：文件、命令、实际输出、遗留问题。失败不得把状态标完成。

不要整段照抄本文的伪算法；先确认 AST/类型定义后写适配代码。不得为让示例通过而修改示例的预期，除非规范或用户确认改变。

## 6. 阶段 A：修补已有确定规则

### S00 建立可复查基线与规则矩阵

- **依赖**：无。**修改范围**：文档，不改业务实现。
- 记录 `git status --short`、当前 HEAD、实际文件列表、fmt/check/test 结果；基线失败与新引入失败分别记录。
- 依据 AST 的全部 Item/Statement/Expression/TypeExpr 变体及 design §3–§10，创建 `docs/sema-coverage.md`。每行必须有：规则 ID、设计依据、实现函数、已实现/部分/缺失/待决策、正反例、验证证据、依赖的 D/S 编号。
- 为模块/导入/可见性/别名/泛型/字面量/声明/表达式/控制流/异常/异步/装饰器各建行；不能只搜 TODO，也不能只列 HIR 支持的语法。
- 将 sema-phase1 文档标为历史计划，并在顶部指向本计划/矩阵；保留历史已确认决策，修正“待开工”状态，不重写成完成报告。
- **验收**：每个 AST 变体能对应矩阵条目；既有实现不会被误列为完全未实现。

### S01 入口规则与现有声明约束

- **依赖**：S00。**位置**：`check/decl.rs::check_main_entry`、`check/type_defs.rs`。
- main 返回类型仅接受 Void / Int(I32)，别名归一化到同类型可接受；保留无参、无泛型、非 extern/async 规则。
- 逐条核对 extern、struct 禁继承/特殊方法、重复参数/成员等已定约束；已经正确的代码保留。
- **正例**：`func main() {}`、`func main() -> int { return 0; }`。
- **反例**：`func main() -> i64 { return 0; }`；已有非入口模块不要求 main。
- **验收**：错位在 main 声明；不修改“返回注解缺省 void”；不新增 extern 必须显式写 void 的规则（design 当前仅要求显式参数类型）。

### S02 f-string 坐标与语义产物一致性

- **依赖**：S00。**位置**：`typecheck/expr.rs::{check_fstring_interpolation,adjust_diagnostics}`、core decor 既有工具。
- 给带前导空格、中文和两个插值的字符串写正反例；分别检查 diagnostics、BindingTable.references 和 expression_types 的源码坐标。
- 子 AST 在进入 check_expr **之前**统一变换到宿主文件字节坐标，或提供统一的检查坐标映射；先评估最小改法，不能只修诊断。需要通用 AST 遍历 API 时先提交具体设计，不立即扩大公开面。
- trim 必须计入被去除的前导字节；不能按字符数算 byte offset；注释交给 parser preprocess，删除本路径重复过滤。
- 确保两个插值不以相同局部 Span 覆盖类型表，也不与主文件表达式的键碰撞；同一条诊断只平移一次。
- **验收**：`f"中文 {  missing } {known}"` 中 missing 诊断精确指向原文件；known 的跳转/重命名范围也正确；跨文件位置不串；原主文件语法产物仍只加载一次。

### S03 统一期望类型检查入口

- **依赖**：S02。**位置**：`typecheck/expr.rs`、body.rs、call.rs、unsafe_rules.rs、mod.rs。
- 扩展 check_expr_with_hint：括号、数组、元组、三元及已有 match 分支递归传递可用提示；不要把“期望类型”强写为不兼容表达式的实际类型。
- return、调用/默认实参、赋值、字段初始化、with 注解统一在已有目标类型下检查。调用实参必须在取得参数对应关系后检查，不能先用无提示路径错误拒绝再补提示。
- 错误分支仍遍历需要检查的子节点；每个实际表达式类型都经统一登记出口记录，避免漏表或重复诊断。
- **正例**：`func f() -> i32[] { return []; }`；`func take(v: i32[]) {} func main() { take([]); }`；嵌套元组中的空数组有明确元素注解。
- **反例**：无上下文空数组仍报错；把 string 实参传给 i32 仍报错；已定型 i32 不能隐式传给 i64。
- **验收**：三份类型表与声明/调用真实类型一致；同一例子在变量/返回/调用位置没有意外差异。

### S04 字面量值解析与目标范围（拆成三个小任务）

- **依赖**：S03；不明确的格式走 D07。**位置**：`ty.rs::classify_number_literal`、`typecheck/expr.rs::check_literal`；必要时拆私有 literals 模块。
- **S04a 整数**：解析进制/下划线、使用足够宽的中间表示或保留符号+幅值，不能先转 i64 丢掉合法 u64。处理一元负号与最小负数边界。目标类型检查覆盖变量、参数、返回、字段、默认值及嵌套聚合；无注解按已定 int/i32 规则检查。
- **S04b 浮点**：拒绝溢出产生的非有限值，核对已定 f32/f64 边界；f8/f16 无明确格式时登记 D07，禁止猜精度。usize/isize 用明确目标设置，不能因开发机是 64 位就永久写死跨平台语义；目标接口变更需先评审。
- **S04c 字符串**：普通/raw/f 前缀、单双引号、已定义转义统一验证；插值扫描处理转义引号/花括号，未定义语法不能自行扩展。统一 sema 与 HIR 的解码规则，避免 sema 接受后 HIR 误解内容。
- **整数验收对**：u8 的 255/256、i8 的 -128/-129、u64 最大值/超一、负数赋给无符号、十六进制等价边界。数值必须用脚本计算，不能靠模型心算。
- **验收**：合法 u64 不因 HIR 的 i64 常量载荷而被 sema 错拒；将 HIR 载荷不兼容记入 S13 必须修复项，不允许悄悄截断。

### S05 声明分阶段与源码顺序无关性

- **依赖**：S03。**位置**：`lib.rs::analyze_with`、`check/type_defs.rs`、`check/decl.rs`、`typecheck/mod.rs::check_field_initializer`、resolve.rs。
- 先复现：同一 struct 中“方法在前、推导字段在后”与反向排列；调用位于被调声明前；跨模块互引与字段初值引用。
- 查明类型注册、字段回填、默认实参和函数体检查的依赖。仅在出现实际差异时修正，不重做已正确的声明收集。
- 必须先完成可确定声明类型，再检查依赖其类型的函数/方法体；推导依赖需要检测循环或未解析，不能固定跑两遍或吞 Unknown。
- 若需重新安排多个阶段，先写具体阶段输入/输出与变更文件，确认后实施。不要通过重复检查函数体制造重复引用/诊断。
- **验收**：允许前向引用的声明换序后诊断和类型投影一致；真正推导环有可定位诊断，不死循环、不无限递归。

### S06 返回路径完整性

- **依赖**：S03。**位置**：新增私有 `typecheck/flow.rs`，在函数/方法/lambda 体入口调用；不把 body.rs 继续堆成巨型文件。
- 使用可表达“正常落出/return/throw/break/continue”的控制流结果，顺序组合与分支取并集；不要只搜是否出现 return，也不要只用一个 always_returns 布尔处理全部语句。
- 非 void、有体函数只要存在正常落到结尾的路径就报错；缺省 void 不改为自动推导。
- if 无 else 有落出；循环一般保留零次执行路径。仅对无条件或可确认恒真的循环且无可达 break 的情况消除正常落出。
- lambda 单独分析；嵌套 lambda 的 return 不能满足外层函数。try/catch/finally 必须考虑 finally 覆盖返回/抛出，不能因 HIR 暂拒绝而跳过 sema 分析；未确定异常规则走 S12。
- **反例**：`func f(n: boolean) -> i32 { if (n) { return 1; } }`。
- **正例**：if/else 均返回、直接 return、合法永不落出的无条件循环；纯 extern/抽象声明不要求函数体返回。
- **验收**：break 不当作 return，continue 不逃出循环；任何尚不能正确分析的 AST 语句必须明确登记，不能默认“必返回”。

### S07 错误恢复、无效输入与递归健壮性

- **依赖**：S01–S06 已完成子项；可先核对独立部分。**位置**：resolve/typecheck/diagnostics 调用链。
- 审查 Unknown/Error/External 每个来源，记录“已报错”“语言允许不透明”“尚未实现”。逐步把已报错路径改为 Error 传播，避免一处未定义引发多个不兼容诊断；不改变 std 暂作 External 的已定行为。
- 对坏导入、循环别名、继承环、非法类型和深层合法表达式检查不 panic/abort。parser/AST 已有分段栈，sema 的递归检查、类型遍历和深 clone/drop 仍须单独验证；复用现有工程方案，不擅自设置很低的嵌套上限。
- 数万层压力输入必须子进程运行并设置进程超时，避免 abort 带走执行器；超时后不能据此宣称通过。
- 模块回归矩阵不能省略：循环导入/同文件不同路径去重；相对、@:/super:/std:；缺 nov.toml；具名导入别名冲突/私有符号；命名空间类型；循环别名；跨文件同名类型与原始诊断路径。先保留现有已定的 pkg/std 降级规则，不自行扩展包系统或标准库。
- 若矩阵发现具体未覆盖规则，按“最小复现→依据→指定修复函数→正反例”的模板补为 S07 子项；不能只在最终报告写一句“导入系统待完善”。
- **验收**：错误之后的独立声明仍检查；错误位置属于正确模块；无重复诊断树；深层支持范围有实测证据和限制记录。

### S08 已定规则的 HIR 一致性修正

- **依赖**：S03、D01 中需要确认的部分。**位置**：HIR build/operators.rs、lvalue.rs、交接文档。
- 普通赋值遵守 design §9.2：先求 RHS 并保存值快照，再定位 LHS，一侧都只能求一次。复合赋值单独按确认规则实现，不机械套用普通赋值。
- 反例必须有双方副作用：`a[index()] = value()`；记录 value/index 的调用顺序，不能只看最终整数结果。
- 更新既有 HIR 冒烟与交接文档的顺序约定；这属于纠正已交付不一致，不能宣称此前已经验证规范正确。
- **验收**：生成的 HIR 指令顺序直接可查；必要的临时执行验证仅验证这一点，不扩建解释器。

## 7. 阶段 B：补齐语言能力，严格经过决策门

### S09 成员身份、静态访问与可见性

- **依赖**：S05、D02。**位置**：ty.rs 的 FieldDef/MethodSig；`check/type_defs.rs`；`typecheck/member.rs`；TypeSummary 与 BindingTable 消费者。
- **S09a** 保存成员定义模块、属主、声明位置/name_span、可见性；在原有继承查询结果中带回真实定义，不只返回裸字段类型。先评审公共投影改动。
- **S09b** 按确认规则检查 pub/pri/默认权限及 static/实例访问，不能把所有字段一律当非静态。继承查询遇子类同名成员时先判遮蔽/覆写规则，不因 static_only 过滤而意外越过子类去找到父类。
- **S09c** 统一 self/this：静态方法没有实例接收者；普通参数不能冒充接收者；检查显式 self 注解、非首位 self、通过类型/实例获取方法等边界。
- **S09d** 将字段与方法的引用记入 BindingTable，LSP 跳转指向成员名字，不能选中整段方法体。
- **验收**：同模块/跨模块、父子类、实例/类型、pub/pri 的矩阵；字段/方法跳转和重命名精确；现有 struct 接收者不回退为副本。

### S10 继承覆写、抽象成员与 trait

- **依赖**：S09、D02/D04。**位置**：ty.rs::TraitDef、`check/type_defs.rs`、member.rs、call.rs::check_new。
- **S10a** 注册并检查 trait 字段/方法签名、重复成员、默认值/方法体（只实现确认允许的形态），公开摘要不再输出空成员。
- **S10b** 检查已定的覆写兼容与抽象需求；new 目标为抽象类时按规则诊断，构造器继承规则不能靠普通成员查找偶然决定。
- **S10c** 实现 class→trait 关系与兼容检查。若 AST 没有承载实现关系，先给最小语法/AST/文法/消费者变更方案并等待确认，不编造推断关系。
- **验收**：缺成员、错签名、重复/非法覆盖、合法实现各有例；跨模块 trait 身份正确；不能只新增类型容器而漏掉体检查。

### S11 泛型类型身份与实参代入

- **依赖**：S05、S09、D05；此项涉及结构性类型改动，必须先评审，不整批盲改。
- **S11a** 写内部表示方案：具名实例保留 args；类型参数按声明身份而非单独名字 T 标识；函数签名保留形参身份和确认的约束。列出所有穷尽 match、相等/可赋值、显示和公共投影消费者。
- **S11b** 先实现显式实参代入函数 params/ret 与类型字段/方法，再处理嵌套数组/元组/指针/函数类型/别名；默认表达式与约束使用定义环境。
- **S11c** 如用户批准推导，再做推导。未批准时缺少必要实参必须明确诊断，不能“没写就浅泛型放行”。实现实例化递归保护；不可用名称缓存错误合并不同实例。
- **验收**：Box<i32> 与 Box<string> 不等价；id<i32>(string) 报错、id<i32>(1) 返回 i32；跨模块同名类型不串；不同函数的 T 不互相污染。
- **边界**：类型检查中的代入与后端单态化分开验收；HIR 尚不支持泛型时仍可明确拒绝，但不能擦除 args 后假装已具体定型。

### S12 复合语义（必须再拆成四批）

- **S12a match，依赖 D06**：在确认范围内做分支结果合一、模式可比性、重复/不可达 case 与穷尽性。先覆盖明确的布尔/默认分支规则，不能声称任意表达式穷尽性可判。将合法无 default 但确实穷尽的值 match 信息提供下游；是否扩充公共投影先评审。
- **S12b 匿名对象与未初始化局部，依赖 D03/D07**：对象结构类型与简写成员绑定按确认方案实现；确定赋值分析复用 S06 控制流，分支汇合取“所有可达路径都初始化”。只做初始化检查，不拓展生命周期分析。
- **S12c 异常/with，依赖 D08**：try 必须有 catch 或 finally；检查 catch 类型、顺序遮蔽、特殊方法签名与调用限制、with 绑定/协议。Exception/std 未建立真实类型时不能假造继承结果。design 允许 `throw;`，当前 AST 是必有 expr 的 Throw：这是 parser/AST 缺口，先提出跨层方案确认再实现；只改 sema 无法补回。
- **S12d async/await，依赖 D08**：建立内部与公开的 Future<T>，async 调用得 Future<T>，await 仅在 async 上下文解包 Future<T>；await 普通值报错。保留同步 main 限制，除非用户批准改变。lambda/default 表达式上下文需核对不能继承错误 async/unsafe/loop 标志。
- **验收**：每批有独立正反例和类型投影检查；静态规则完成与运行时实现完成分别报告，禁止统一写“暂交 codegen”而跳过检查。

### S13 sema 与 HIR/LSP 公共契约收口

- **依赖**：已完成的所有前项。**位置**：sema lib.rs 的投影、HIR ty/build、LSP sema adapter 与功能消费者。
- 核对 expression_types/annotation_types/declaration_types 的职责与 span 唯一性；泛型上下文不能只用单个定义 Span 存不同实例的结果，否则会互相覆盖。
- S04 的合法 u64、新 Future/trait/泛型信息不得投影丢失；消费者不能留 `_ => Unknown` 等掩盖新增类型的分支。
- sema 接受而 HIR 不支持的能力有逐项、稳定、带位置的拒绝；它是后端覆盖限制，不计为 sema 错误。
- 装饰器/宏应单独记录支持状态：当前无展开产物时不可声称已验证展开后的语义，也不能擅自执行未知装饰块；是否收紧成 error 先确定语言/工具模式策略。
- **验收**：已有 HIR 冒烟继续通过；新增类型保真或明确拒绝；LSP 引用位置与 CLI 合并诊断一致，无新增并列诊断字段。

## 8. 验证方式与最终交付

### 临时语义用例的执行方法

每例写入 `/tmp/novella-sema-cases/<规则ID>/main.nov`；跨模块依赖放同目录。每例有合法 main，除非专门验证入口错误。

```bash
rtk cargo build -p novella
rtk proxy target/debug/novella compile /tmp/novella-sema-cases/S01/main.nov -o /tmp/novella-sema-cases/S01/out.json
```

**不能只看命令退出码**：当前 CLI 写出诊断 JSON 后不一定因语义错误退出非零。用 Node 脚本读取 JSON 的 `diagnostics.global` 及 `diagnostics.modules[].diagnostics`；核对 severity、消息关键字、文件及 span。脚本读不到预期结构或 JSON 时必须失败。

- 正例：无 Error；允许哪些 Warning 必须逐项写明。
- 语义反例：词法/语法先通过，再有目标语义错误；不能拿另一处无关错误充数。
- 定位：使用脚本找源码字节位置比较，含中文/emoji 时按 UTF-8 byte offset；LSP 另验 UTF-16。
- 三份类型表与绑定不在当前 CLI JSON 中。需验证它们时，用已有可运行入口或临时 Rust consumer 调公开 analyze API；不要为了验收把内部模块公开，也不要把 HIR 构建成功当作投影完整性证明。
- 对 /tmp 证据列出命令和关键输出并写入执行记录；仅保留临时文件路径不算可复现交付，应把必要最小源码与预期摘要写进文档。

## 9. 推荐执行顺序与接力格式

顺序：S00 → S01 → S02 → S03 → S04a/b/c → S05 → S06 → S07 → S08 → S09a/b/c/d → S10a/b/c → S11a/b/c → S12a/b/c/d → S13 → S14。
