# LLVM 编译缓存

## 范围与入口

`novella build` 默认启用项目本地目标文件缓存。命中后跳过全部前端、HIR 和 LLVM 发射，
重放结构化诊断，再按当前输出路径重新链接。只保存成功通过分析、HIR 降级及代码生成的结果；
链接失败不会使已生成的目标文件无效。源码或代码生成错误不会发布新记录。

`--no-cache` 同时禁止缓存读写，`--verbose` 输出命中或失效原因以及各阶段耗时。
`compile`、`check` 和 AST/HIR 导出保持原流程。

后端支持 Linux x86-64 GNU 与 x86-64 裸机 ELF；共享目标、runtime 和代码模型进入缓存身份。
缓存明确区分宿主身份和目标身份，文件名不依赖 ELF、COFF 或 `.o`/`.obj` 扩展名。

## 输入身份

查找键使用版本化 JSON 编码的有效配置和工具链摘要，经 BLAKE3 生成：

- 缓存格式版本、编译器可执行文件内容摘要。
- 当前进程实际使用的 LLVM 所属文件内容摘要。静态链接时为所属可执行模块；
  Unix 通过 `dladdr` 定位，Windows 通过模块句柄定位。不能定位或读取时禁用缓存。
- 宿主 OS、架构、平台族，以及当前工作目录和入口路径。
- 后端实际目标 triple、目标描述的规范化 JSON、指针宽度、完整条件编译视图
  （键值、flag、排序去重后的 features、`--cfg` 注入值、`--check-cfg` 白名单）、
  标准库根、入口检查模式。

配置先由 CLI 展开为实际传入 sema 的 `AnalysisOptions`，缓存不重新推导默认值。
目标描述整体进入身份，因此自定义目标的任意字段变化都会失效；CPU features 与重定位策略
已包含在描述里，不再依赖编译器摘要兜底。链接脚本和附加对象在每次链接时重新读取，
不复用过期的最终映像。
`-o` 和详细日志开关不影响代码生成，不进入键。

编译内容键由查找键和按观察顺序保存的全部输入记录计算。输入包括：

| 记录 | 编译时采集 | 命中前验证 |
|------|------------|------------|
| 文件读取 | 实际读取文本的内容摘要，包括项目清单和标准库模块 | 重新读取文件计算摘要 |
| 存在性探测 | `nov.toml` 搜索中每个路径的存在与否 | 比较存在状态 |
| 模块键解析 | 入口和每条导入路径经 core 规范化后的模块键 | 重新解析并比较 |

模块键观察发生在去重之前，所以多个导入别名原本指向同一文件，随后其中一个符号链接
重指向其他文件，也会失效。存在性记录包含未命中的清单位置，能检测新增的更近 crate 根。
不依赖修改时间或文件长度；保持原时间戳的内容修改也必须失效。

模块加载仍是导入扫描的唯一实现。`FileLoader::module_key` 默认委托 core 的 `module_key`，
缓存加载器只记录结果；已有文件读取和存在性接口用于采集另外两类依赖。
编译结束后再验证一次记录，输入发生变化时不发布缓存，不用新读取的源码冒充实际编译输入。
和普通文件系统编译一样，这不提供对并发源码修改的事务快照保证。

## 存储协议

```text
target/.novella-cache/v2/
├── records/<查找键>.json
└── objects/<目标文件内容摘要>
```

记录保存版本、查找键、编译内容键、输入列表、目标文件摘要、运行时需求和结构化诊断。
命中后从记录恢复需求，不能重新以符号名或源文件猜测是否需要 managed 归档。
旧 v1 记录不迁移，直接使用 v2 目录重新编译。
诊断只附带其渲染需要的源码，不保存终端颜色文本。整个记录另带校验和，
读取时验证版本、身份、记录校验和、编译内容键、全部输入及目标文件内容摘要。

对象和记录均在各自目录创建临时文件，然后原子替换。先发布完整目标文件，最后发布记录；
同键并发构建可以重复计算，不共享可变半成品。不强制对编译过程加锁，也不承诺断电持久性。
进程正常结束时临时文件自动清理。

记录缺失或正常输入变化视为未命中；记录损坏、对象缺失、校验失败或 I/O 错误会报告并重新编译。
缓存发布失败也会报告，但不会阻止正常生成输出。最终链接沿用输出目录中的临时文件和原子替换，
不从缓存直接恢复可执行文件。

## 边界

- 本地缓存保留实际路径和工作目录，不承诺跨目录、跨宿主或跨机器共享。
- 不缓存失败构建、可执行文件、语法快照、sema、HIR 或 LLVM bitcode。
- 不做模块级目标文件增量；当前 LLVM 以整个 HIR 程序作为发射单元。
- 每次验证工具链及依赖文件内容，存在固定开销，极小程序可能比关闭缓存更慢。
- 当前版本没有容量淘汰或清理子命令；格式升级使用新版本目录。
- Windows 的模块定位分支已提供，但本轮实际构建与运行验证的平台为 Linux x86-64。

代码位置：CLI 的 `build.rs` 负责编排，`cache/` 负责身份、输入、存储与校验，
codegen 的 `identity.rs` 只提供实际 LLVM 模块的位置；sema 不承担缓存存储策略。
